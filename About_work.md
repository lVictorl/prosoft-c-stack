# Реализация стека на языке C

Обзор проекта
=

Проект представляет собой статическую библиотеку на языке C, реализующую структуру данных стек с поддержкой множественных экземпляров и нетипизированным хранением данных. Библиотека предоставляет API для создания, удаления и работы со стеком.

Структура данных стека реализована через структуру с гибким массивом:

"""
typedef struct node_s {
    struct node_s* prev;
    unsigned int size;
    char data[];
} node_t;
"""

Данная структура позволяет объединить данные в единый блок памяти, что исключает дополнительные выделения памяти.


# Система управления стеками

Для управления множественными стеками используется глобальная таблица с динамическим расширением:

"""
c
static struct {
    unsigned int size;
    stack_entry_t* entries;
} g_table = {0, NULL};
"""

Начальный размер таблицы - 10 элементов. При заполнении таблица расширяется в 2 раза. Каждая запись содержит флаг занятости и указатель на вершину стека.

# Функции их ответственность

- Создание и удаление стеков stack_new(): Возвращает наименьший свободный индекс таблицы или расширяет таблицу при необходимости.

- stack_free(): Рекурсивно освобождает все узлы стека и помечает запись как свободную.

### Операции со стеком

- stack_push(): Выделяет память размером (sizeof(node_t) + size) и копирует данные через memcpy.

- stack_pop(): Извлекает данные с ограничением копирования до min(размер_данных_узла, размер_буфера)

- stack_size(): Линейный обход стека для подсчета элементов.

### Валидация и безопасность (проверка на ошибки/обработка ошибок) обеспечивается проверкой в коде следующими функциями:

- stack_valid_handler() возвращает целочисленное значение:
- - 0 - если хэндлер валиден и соответствующий стек существует
- - 1 - если хэндлер невалиден (стек не существует или хэндлер за пределами таблицы)

Проверка валидности хэндлера выполняется через проверку границ и флага занятости.

Все функции проверяют:

- Ненулевые указатели для операций с данными

- Ненулевой размер данных при добавлении

- Существование элементов стека при извлечении


Память для узлов стека выделяется единым блоком, включая метаданные и данные используя массив char data[]. 

Таблица стеков геометрически увеличивается/уменьшается (пока что не уменьшается) для снижения количества пересоздания данной структуры данных (стека). При это не выделяется большой массив памяти, т.к. для, возможно, малого числа данных, данный вариант будет не рационален. 

Операция stack_pop() гарантирует отсутствие переполнения буфера через ограничение копируемого размера.
